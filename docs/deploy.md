# Деплой публичного стенда

Стенд — одна VM с Docker: Caddy (HTTPS) → nginx (фронт) → API → Postgres. Наружу открыты только порты 80 и 443, сертификат Let's Encrypt Caddy получает и продлевает сам.

## Требования к VM

- Linux x86_64 с Docker и Docker Compose v2.24 или новее.
- 2 vCPU и 4 ГБ RAM. Модели эмбеддингов роли 2 (например, bge-m3) нужно 2–4 ГБ, без неё хватит 2 ГБ.
- 20 ГБ диска.
- Белый IP и открытые входящие порты 80 и 443 (TCP) и 443 (UDP, для HTTP/3).

## Адрес сайта

Caddy нужно доменное имя, по голому IP сертификат не выдаётся.

- **Свой домен:** A-запись на IP VM, например `news.example.ru`.
- **Без домена:** имя вида `<IP>.sslip.io`, например `203.0.113.10.sslip.io`. Оно всегда указывает на этот IP, регистрировать ничего не нужно.

## Первый запуск

```bash
git clone <repo> && cd vibe-research
cp .env.example .env
```

В `.env` обязательно задать:

| Переменная | Значение |
|---|---|
| `SITE_ADDRESS` | домен из раздела выше |
| `POSTGRES_PASSWORD` | длинная случайная строка |
| `JWT_SECRET` | длинная случайная строка, иначе после перезапуска всех разлогинит |
| `DEMO_PASSWORD` | общий пароль демо-учёток вместо паролей из `users.json` |
| `CORS_ORIGINS` | `["https://<SITE_ADDRESS>"]` |

Случайную строку можно получить так: `openssl rand -base64 32`.

```bash
make prod-up
```

Через минуту стенд доступен по `https://<SITE_ADDRESS>`. Миграции базы применяются при старте контейнера `api`.

## Перед показом

1. Войти как `demo`, открыть «Качество», нажать «Подготовить инсайты».
2. Пройти сценарий проверки из README.
3. Сделать резервную копию: `make backup`.

## Обслуживание

| Задача | Команда |
|---|---|
| Логи | `make prod-logs` |
| Обновить код | `git pull && make prod-up` |
| Резервная копия | `make backup` (файл в `backups/`) |
| Восстановить копию | `gunzip -c backups/<файл>.sql.gz \| docker compose exec -T db psql -U alfa alfa_news` |
| Остановить | `make prod-down` (данные в томах сохраняются) |

## Безопасность

- В Docker-сети наружу смотрит только Caddy. nginx, API и Postgres портов на хост не публикуют.
- Адрес клиента для лимита попыток входа берётся из заголовка, который ставит Caddy. Подделать его клиент не может: это проверено.
- Caddy добавляет HSTS, `X-Frame-Options: DENY`, `nosniff` и убирает заголовок `Server`.
- Лимиты на запуск агента, чат и приём новостей задаются в `.env` (`RATE_LIMIT_*`). Они защищают общий дневной бюджет LLM.
