## Блокирующие вопросы

### 1. Сигнатура `rank(profile, events) -> list[FeedItem]`

**Да, оставляем как в `ProfilePort`.** `rank` — чистая функция: без БД, без LLM, детерминированная (одинаковый вход даёт одинаковый порядок, при равном скоре порядок по `event_id`). BFF сам достаёт кандидатов через `NewsPort.list_events` и передаёт их вместе с профилем. Так модуль тестируется без Postgres, а ингест и ранжирование не завязаны на общую схему БД.

Если событий станет много (тысячи), добавлю `prefilter(profile) -> {tags, okved_sections, countries}`, чтобы BFF отбирал кандидатов в SQL. Пока не нужно.

Реализация: `CsvProfiles` в `app/profiling/service.py`, подключена в `registry.py` через переменную окружения:

```
PROFILES_DATA_DIR=app/profiling/synthetic_data   # путь от backend/
PROFILES_PINNED=["c-001","c-002","c-003","c-004","c-005","c-006"]
PROFILES_REVENUE_MULTIPLIER=                      # пусто = угадать единицы выручки
```

Если `PROFILES_DATA_DIR` пустая, работают твои заглушки, как сейчас. Работает и при `MOCK_MODE=true`: новости и агент остаются заглушками, профили и лента берутся реальные.

### 2. `why_relevant`

**Да, причины — основа скора.** `score = (сумма весов причин) × (0.5 + importance) × свежесть`. Каждая причина, которая добавила вес, становится чипом, поэтому чипы честно объясняют позицию в ленте. Причины отсортированы по весу, одинаковые подписи склеены.

Типы причин (поле `feature`):

| `feature` | Пример подписи |
|---|---|
| `okved`, `products.credit`, `foreign_trade`, … | «Кредиты: ставка определяет стоимость долга», «Металлы: ключевой фактор для отрасли «металлургия»» |
| `okved` (событие прямо про отрасль) | «Новость о вашей отрасли: металлургия» |
| `counterparty.<id>` | «Затронут ваш покупатель: металлургия, 74% поступлений» |
| `foreign_trade.countries` | «Страна вашей ВЭД: Китай» |
| `region` | «Ваш регион: Краснодарский край» |
| `macro` | «Касается всей экономики» |

В `RelevanceReason` добавлено поле `weight` (вклад в скор). Для UI советую показывать 3 первых чипа, остальные под «ещё».

### 3. Схема `ClientProfile` против колонок CSV

Я сверил с Приложением 1 из ТЗ. Все изменения **только добавляют поля** (по правилу контрактов), твои фикстуры валидны.

Что не совпадало с данными:

- `company_age_years` и `employees` в CSV — это **градации-строки** (`COMPANY_AGE_YEARS_GRADATION`, `AMOUNT_WORKERS_*_GRADATION`), а не числа. Оставил оба поля и кладу в них середину диапазона, а сырое значение — в новые поля `company_age_gradation` и `employees_gradation`. В UI лучше показывать градацию.
- `debt_load` в CSV напрямую нет. Считаю по числу долговых продуктов в Альфе (кредит, лизинг, факторинг): 1 = low, 2 = medium, 3 = high. `none` ставлю только действующему клиенту с заполненными флагами. Сумм долга в данных нет, и кредиты в других банках не видны: это записано в `data_quality.notes`.
- Страны ФТС в CSV по-русски. Перевожу в ISO-2 (`countries`), как в `Event`, и сохраняю исходные названия в `country_names`.

Новые поля:

| Поле | Откуда | Зачем |
|---|---|---|
| `sector` (и в `ClientSummary`) | ОКВЭД → укрупнённый сектор | Подпись в списке клиентов и чипах |
| `org_type`, `ownership_form`, `business_stage`, `key_owner_mark` | `ORG_TYPE`, `OKFS_NAME`, `ECO_MARK_LABEL`, `NEGATIVEMARK` | Были в CSV, но не в схеме |
| `Sensitivity.direction` | правила | риск / возможность / смешанно: агенту проще сформулировать вывод |
| `Sensitivity.evidence` | правила | Ключи признаков (`products.credit`, `okved`, `foreign_trade`, `counterparty.<id>`) для панели «Как получен вывод» (критерий 12) |
| `Counterparty.sector`, `payments_count`, `tags` | граф платежей | Влияние второго порядка через контрагентов |
| `counterparty_concentration` | HHI по объёму платежей | Зависимость от одного контрагента |
| `affiliates` | `GROUP_ID` + общие физлица | Скрытые связи помимо группы |
| `data_quality` | профайлер | `missing_fields`, `notes`, `completeness` 0..1 (ограничение 5 про неполные данные) |

`display_name` генерирую сам: `Сектор · Регион · #xxxx` (последние 4 символа id), например «Металлургия · Свердловская обл. · #c001». Данные обезличены, придумывать «названия компаний» не стал.
